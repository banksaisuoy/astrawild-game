# ASTRAWILD: เสียงสะท้อนแห่งรุ่งอรุณ

## Master Project Plan สำหรับ Unreal Engine

**ฉบับ:** 1.0 — Pre-production package  
**แนวเกม:** Third-person cooperative survival adventure, creature companionship, exploration และ base building  
**แพลตฟอร์มเริ่มต้น:** PC Windows; Single-player เป็นแกน, Co-op 1–4 คนเป็นระยะขยาย  
**เครื่องมือหลัก:** Unreal Engine 5.x, C++ สำหรับระบบแกนกลาง, Blueprint สำหรับคอนเทนต์และการปรับจังหวะ  
**เป้าหมายภาพรวม:** เกมโลกกว้างที่เล่นสนุกจริงบนเครื่องระดับกลาง มีอีโคที่มีตัวตน ระบบฐานที่มีความหมาย และสถาปัตยกรรมที่ขยายต่อได้

> **คำประกาศของเกม:** ผู้เล่นไม่ได้ออกไปสะสมสิ่งมีชีวิตเพียงอย่างเดียว แต่กำลังสร้างความสัมพันธ์กับโลกที่กำลังฟื้นตัว ทุกอีโคมีที่มา พฤติกรรม และประโยชน์ต่างกัน การเลือกว่าจะช่วย ฝึก ใช้ หรือปล่อยให้มันอยู่ตามธรรมชาติจะทำให้การเดินทางของแต่ละทีมมีเรื่องราวไม่เหมือนกัน

## 1. สรุปการตัดสินใจหลัก

ASTRAWILD จะสร้างด้วย Unreal Engine เป็นโปรเจกต์ PC-first และไม่เริ่มจาก MMO หรือ Mobile เพราะเกมแนวนี้มีความเสี่ยงสูงทั้งด้านโลกกว้าง AI ระบบบันทึก และการทำงานร่วมกันของผู้เล่น การเริ่มจาก Single-player ที่มี Co-op-ready architecture ทำให้พิสูจน์ความสนุกได้เร็วและยังรักษาความเป็นไปได้ในการขยายเป็นเกมใหญ่

| เรื่อง | คำตัดสินใจ |
|---|---|
| กล้อง | Third-person ปรับระยะได้ รองรับเมาส์ คีย์บอร์ด และคอนโทรลเลอร์ |
| Core loop | เตรียมตัว → สำรวจ → พบอีโค/ทรัพยากร/เหตุการณ์ → ตัดสินใจ → กลับฐาน → คราฟต์/ฝึก/ขยาย → เปิดพื้นที่ใหม่ |
| อีโค | สิ่งมีชีวิตต้นฉบับ มีบุคลิก ความต้องการ ความสามารถภาคสนาม และบทบาทงานฐาน |
| ฐาน | Modular snap building มีการผลิต ฟาร์ม พลังงาน ความปลอดภัย และพื้นที่ตกแต่ง |
| โลก | 3–5 เขตเมื่อเปิดตัว โดยเริ่มทำ Vertical Slice หนึ่งเขตขนาดย่อม |
| Multiplayer | Co-op 1–4 คน ใช้ server authority; Host/Listen Server ในช่วงทดสอบก่อนพิจารณา Dedicated Server |
| กราฟิก | Stylized naturalism; High/Ultra ใช้ Nanite/Lumen มากขึ้น, Medium/Low ต้องเล่นได้และอ่านสถานะครบ |
| Performance target | 60 FPS บนเครื่องระดับกลางในฉากทั่วไป; 30 FPS เป็นขั้นต่ำชั่วคราวในฉากหนัก โดยไม่ให้มี hitch รุนแรง |
| สิ่งที่ยังไม่ทำ | MMO, Mobile, ระบบเติมเงินที่กระทบเกมเพลย์ และโลกขนาดมหาศาลก่อน Core loop ผ่าน |

## 2. วิสัยทัศน์และตัวตนของโลก

เรื่องราวเกิดหลัง “รุ่งอรุณแตกสลาย” พลังงานจากแกนโลกไหลขึ้นสู่พื้นผิว ทำให้ธรรมชาติเติบโตอย่างผิดปกติ เครื่องจักรเก่าเสียหาย และสิ่งมีชีวิตบางส่วนกลายเป็น “อีโค” ผู้เล่นเป็นสมาชิกคณะสำรวจที่เดินทางมายังทวีปเวลดารา เพื่อตามหาต้นตอของพลังงานและเปิดใช้งานหอดูดาวโบราณห้าแห่ง

โลกแบ่งเป็นเขตที่มีสภาพแวดล้อม ระบบนิเวศ ชุมชน และความขัดแย้งแตกต่างกัน พื้นที่ต้องมี landmark ที่อ่านได้จากไกล เส้นทางหลักที่ปลอดภัย เส้นทางรองที่เสี่ยงแต่ให้รางวัล และจุดลับที่ให้รางวัลกับการสังเกต ไม่ใช่เพียงการเปิดแผนที่ให้ครบ

| เขต | ประสบการณ์ | ระบบเด่น | ขอบเขตเปิดตัวเบื้องต้น |
|---|---|---|---|
| ทุ่งอรุณ | เขตเริ่มต้นและจุดสร้างความเข้าใจ | เก็บของ จับอีโค คราฟต์ ฐาน และบอสแรก | อีโค 8 ชนิด, เควสต์หลัก 6 ตอน |
| ป่าฝนเรืองแสง | ป่าหนาแน่นและแสงจากธรรมชาติ | ความชื้น พิษ พรางตัว และการติดตามร่องรอย | อีโค 10 ชนิด, ดันเจียน 2 แห่ง |
| ที่ราบเกลือ | พื้นที่ร้อน โล่ง และพายุฝุ่น | อุณหภูมิ น้ำ การเดินทางไกล และพาหนะ | อีโค 8 ชนิด, สนามท้าทาย 1 แห่ง |
| แนวหิมะคราม | พื้นที่แนวตั้งและสภาพอากาศรุนแรง | ความหนาว ปีนผา เชือก และถ้ำน้ำแข็ง | อีโค 8 ชนิด, หอดูดาว 1 แห่ง |
| ซากมหานครเวลดารา | เมืองโบราณที่ระบบรักษาความปลอดภัยเสียหาย | ปริศนา ไฟฟ้า เครื่องจักร และการลอบเร้น | อีโค 6 ชนิด, เรด 1 แห่ง |

โลกจะใช้ World Partition เพื่อจัดการ persistent world ที่แบ่งเป็น grid cell และโหลดตาม streaming source โดยทำงานร่วมกับ One File Per Actor, Data Layers, Level Instancing และ HLOD ซึ่งเป็นแนวทางที่เอกสาร Unreal แนะนำสำหรับโลกขนาดใหญ่ [1]

## 3. ประสบการณ์และวงจรการเล่น

เกมจะทำให้ผู้เล่นมีเหตุผลที่จะออกจากฐานและมีเหตุผลที่จะกลับฐานเสมอ ผู้เล่นเตรียมอุปกรณ์และอีโค ออกสำรวจ เก็บข้อมูลหรือทรัพยากร พบเหตุการณ์ เลือกวิธีจับหรือแก้ปัญหา แล้วกลับมาแปรรูปสิ่งที่ได้เป็นเทคโนโลยี อาหาร อุปกรณ์ หรือสิ่งปลูกสร้างใหม่ วงจรนี้ต้องสร้างความรู้สึกก้าวหน้าโดยไม่บังคับให้ผู้เล่นฟาร์มตัวเลขเดิมซ้ำอย่างไร้ความหมาย

การเล่นจะมีสามชั้นที่เชื่อมกัน คือการควบคุมตัวละครและการต่อสู้ การตัดสินใจเชิงระบบระหว่างสำรวจ และการพัฒนาฐาน/ความสัมพันธ์ การต่อสู้ควรชนะด้วยการอ่านพฤติกรรมและจัดทีม ไม่ใช่เพียงค่าพลังชีวิตสูงกว่า การสร้างฐานควรช่วยให้เดินทางไกลขึ้น ไม่ใช่เป็นหน้าจอจัดของที่แยกจากโลก

| เวลาเล่น | ประสบการณ์ที่ต้องการ |
|---|---|
| 30 วินาทีแรก | ผู้เล่นเคลื่อนที่ กล้อง และการโต้ตอบได้โดยไม่ติดเมนู |
| 3–8 นาที | พบสิ่งใหม่ ร่องรอย หรือทรัพยากรที่มีความหมาย |
| 15–30 นาที | ได้อีโคหรืออุปกรณ์ที่ทำให้ทางเลือกเพิ่มขึ้น |
| 45–90 นาที | จบ core loop หนึ่งรอบและเห็นผลจากการกลับฐาน |
| ระยะยาว | พื้นที่ใหม่ ความสัมพันธ์ใหม่ และวิธีเล่นที่ต่างกัน |

## 4. ตัวละคร อีโค และความสัมพันธ์

อีโคต้องถูกออกแบบจาก habitat, silhouette, behavior, utility และ emotional hook ไม่ใช่เพียงนำสัตว์จริงมาบวกเขาหรือปีก แต่ละชนิดต้องมีบทบาทที่ทำให้ผู้เล่นอยากทดลอง เช่น การต่อสู้ การขนส่ง การปีน การว่ายน้ำ การตรวจร่องรอย การทำงานฐาน หรือการควบคุมพื้นที่

อีโคหนึ่งตัวมี Definition ID ที่คงที่ และ Instance ID เฉพาะของผู้เล่น ค่าความไว้ใจ บุคลิก ความเหนื่อยล้า ความสามารถ และสายพัฒนาแยกจากข้อมูลรูปลักษณ์ ทำให้ทีมปรับสมดุลหรือเพิ่ม variant ได้โดยไม่ทำลาย save เดิม

| ระบบอีโค | รายละเอียด |
|---|---|
| การค้นพบ | สมุดภาคสนามค่อย ๆ เติมจากการสังเกต ติดตาม ให้อาหาร ต่อสู้ และช่วยเหลือ |
| การจับ | ใช้อุปกรณ์ สร้างความไว้ใจ หรือช่วยจากอันตราย; ผลลัพธ์ต่างกันตามวิธี |
| ความสัมพันธ์ | รู้จัก → คุ้นเคย → ไว้ใจ → ผูกพัน → คู่หู |
| ความสามารถ | ธาตุ/สถานะ, ความสามารถภาคสนาม, งานฐาน และความสามารถร่วมทีม |
| ความเหนื่อยล้า | การใช้งานต่อเนื่องโดยไม่พักลดประสิทธิภาพ ทำให้การหมุนเวียนทีมมีความหมาย |
| ความแตกต่าง | อีโคที่ไม่หายากอาจมีบุคลิกหรือ utility ที่เหมาะกับทีมเฉพาะทาง |

## 5. การควบคุม การเอาชีวิตรอด และการต่อสู้

ผู้เล่นมีการเดิน วิ่ง กระโดด หลบ ปีน ว่ายน้ำ ใช้อุปกรณ์ และโต้ตอบกับสิ่งแวดล้อม การควบคุมต้องตอบสนองเร็วและมีระบบกันติด กล้องไม่ควรชนฉากหรือทำให้ตัวละครหายระหว่างต่อสู้ การตั้งค่าต้องรองรับการ remap ปุ่ม ความไวกล้อง การกลับแกน การสั่นจอย toggle/hold และช่วยเล็ง

สถานะเอาชีวิตรอดใช้จำนวนจำกัดเพื่อไม่ให้ผู้เล่นเฝ้าดูตัวเลขตลอดเวลา พลังชีวิตและความอึดเป็นสถานะหลัก ส่วนความหิว ความกระหาย อุณหภูมิ และพิษใช้เฉพาะพื้นที่หรือกิจกรรมที่มีเหตุผล มีสัญญาณเตือนก่อนเกิดผลรุนแรง และมีแหล่งแก้ไขที่ผู้เล่นค้นพบได้

การต่อสู้มีโจมตีเบา หนัก ระยะไกล สกิล อาวุธ สลับอีโค คำสั่งทีม และสถานะธาตุ ศัตรูจะมี telegraph, hit reaction, จุดอ่อน และพฤติกรรมตอบสนอง เช่น หนี เรียกฝูง หรือเปลี่ยนรูปแบบเมื่อพลังชีวิตลด บอสต้องเปลี่ยนกติกาของสนามหรือรูปแบบการโจมตี ไม่ใช่เพิ่มเลือดอย่างเดียว

## 6. ฐาน คราฟต์ และเศรษฐกิจ

ฐานเป็นพื้นที่ที่ผู้เล่นเห็นผลจากการตัดสินใจ แบ่งเป็นที่พัก การผลิต ฟาร์ม วิจัย ฝึกอีโค พลังงาน ป้องกัน และตกแต่ง อีโคทำงานผ่านลำดับความสำคัญและเงื่อนไขง่าย ๆ ไม่ต้องควบคุมทุกก้าว ระบบสร้างใช้ modular snap ที่ preview ได้ชัด วาง ย้าย และรื้อได้โดยไม่ลงโทษผู้เล่นมากเกินไปในช่วงต้น

สูตรคราฟต์และทรัพยากรต้องมีความแตกต่างเชิงการใช้งาน วัตถุดิบควรทำให้ผู้เล่นเข้าถึงพื้นที่หรือทางเลือกใหม่ ไม่ใช่เพิ่มชื่อของที่เหมือนกันหลายแบบ เศรษฐกิจใช้การแลกเปลี่ยนกับชุมชนเพื่อลดการฟาร์มซ้ำ แต่ไม่ควรทำให้คราฟต์หมดความหมาย

## 7. เควสต์ เรื่องราว และ Co-op

เควสต์หลักติดตามหอดูดาวและความจริงของรุ่งอรุณแตกสลาย เควสต์รองใช้สถานะโลกสร้างเรื่องราว เช่น ฝูงอีโคหาย ชุมชนขาดน้ำ เครื่องจักรทำงานผิด หรืออีโคที่เคยช่วยกลับมานำทาง การตัดสินใจส่งผลในขอบเขตที่ดูแลได้ เช่น เปิดร้าน ย้ายทรัพยากร เปลี่ยน NPC หรือเพิ่มเหตุการณ์เฉพาะเขต ไม่เริ่มด้วย branching story ขนาดมหาศาล

Co-op 1–4 คนเป็นการแบ่งหน้าที่แบบยืดหยุ่น ผู้เล่นหนึ่งสร้างฐาน อีกคนสำรวจ อีกคนดูแลอีโค หรือทุกคนรวมทีมต่อสู้ก็ได้ ข้อมูลแบ่งเป็น Player, Party, World, Base และ Temporary Event อย่างชัดเจน เจ้าของโลกควบคุมการปลดล็อกโลก แต่ผู้มาเยือนต้องเก็บอุปกรณ์ ความรู้ และความสัมพันธ์ของตนเองได้

## 8. Unreal Engine Architecture

ระบบแบ่งเป็นโมดูล `AstrawildCore`, `AstrawildGameplay`, `AstrawildWorld`, `AstrawildBuilding`, `AstrawildProgression`, `AstrawildSave`, `AstrawildNet`, `AstrawildUI` และ `AstrawildEditor` โดย C++ รับผิดชอบกฎที่ต้องเสถียร ความถูกต้อง และประสิทธิภาพ ส่วน Blueprint ใช้ประกอบคอนเทนต์และต้นแบบ

| ชั้น | องค์ประกอบ |
|---|---|
| Framework | GameInstance, GameMode, GameState, PlayerController, PlayerState, Character |
| Gameplay | Gameplay Ability System, Attributes, Effects, Tags, Damage และ Status |
| Data | Primary Data Assets, Data Tables, Stable IDs และ Schema Version |
| World | World Partition, Data Layers, HLOD, World Subsystems และ Spawn Simulation |
| AI | StateTree/Behavior Tree สำหรับใกล้ผู้เล่น; lightweight/Mass simulation สำหรับไกล |
| Persistence | Player Profile, World Snapshot, Settings, Migration, Checksum และ Backup |
| Network | Server Authority, Relevancy, Rate Limit, RPC Validation และ Replication |
| UI | ViewModel/MVVM, HUD, Map, Journal, Inventory, Settings และ Accessibility |

อีโคใกล้ผู้เล่นใช้ Actor เต็มรูปแบบ ส่วนอีโคไกลลด tick/animation และอาจใช้ lightweight state หรือ Mass Entity ซึ่งเป็น framework สำหรับการคำนวณแบบ data-oriented [2] ไม่ควรนำตัวละครที่ผู้เล่นกำลังควบคุมไปไว้ในระบบที่ทีมยังไม่ชำนาญทั้งหมดในครั้งเดียว

ระบบสร้างฐานและการจับอีโคต้องคำนวณ preview ฝั่ง client เพื่อความลื่น แต่การยืนยันต้องเกิดฝั่ง server การสร้างไอเทม ดาเมจ ตำแหน่ง การจับ และการเปลี่ยนสถานะเควสต์จะไม่รับผลลัพธ์จาก client โดยตรง

## 9. ระบบบันทึกและความปลอดภัย

Save แบ่งเป็น `PlayerProfile`, `WorldSnapshot` และ `SettingsProfile` ใช้ Stable ID, Schema Version และ Migration Chain ตั้งแต่ไฟล์แรก การเขียนใช้ temporary file และ atomic rename พร้อม checksum มี backup อย่างน้อยสามช่อง และแยก backup ของตัวละครออกจากโลกเพื่อป้องกันความเสียหายลามทั้งชุด

ทุก RPC ต้องตรวจสอบระยะ สิทธิ์ cooldown สถานะ และข้อมูลประกอบ Rate limit ใช้กับการเรียกซ้ำ และระบบต้องรองรับการหลุดระหว่างธุรกรรมด้วย command ID และ rollback หากใช้ Iris ต้องประเมินใน branch แยก เนื่องจากเอกสาร Epic ระบุว่าเป็นระบบ opt-in และยังมีสถานะ Experimental ในเอกสารรุ่นปัจจุบัน [3]

## 10. Art Direction และระบบกราฟิก

สไตล์คือ stylized naturalism: โลกมีแสงและวัสดุที่น่าเชื่อ แต่ silhouette และสีของอีโคต้องจำได้จากไกล สีธรรมชาติเป็นพื้นฐาน พลังงานเรืองแสงใช้เฉพาะจุดสำคัญเพื่อรักษาลำดับความสนใจ สีของสถานะไม่ควรเป็นข้อมูลเพียงชนิดเดียว ต้องมี icon, pattern, shape และเสียงสำรองเพื่อรองรับผู้เล่นที่แยกสีได้ยาก

Nanite ใช้กับ static environment, cliffs, rocks, ruins และ asset ที่เหมาะสม แต่ต้องมี fallback mesh และตรวจ material, instance, shadow, memory และ output resolution เพราะ Nanite ลดภาระ geometry ได้มากแต่ยังมีข้อจำกัดเชิงปฏิบัติ [4] Lumen ใช้ใน High/Ultra และลดคุณภาพหรือเปลี่ยนวิธีแสงใน Medium/Low ตามผลทดสอบจริง เพราะต้นทุนขึ้นกับ scene distance, final gather และ reflection quality [5]

เสียงแบ่งเป็น ambience, diegetic gameplay, vocal, UI และ adaptive music เสียงฝีเท้า สัญญาณอันตราย และเสียงอีโคช่วยให้ผู้เล่นรับรู้โลกโดยไม่ต้องเพิ่มไอคอนทุกจุด ดนตรีใช้ layer ตาม exploration, tension และ combat และต้องแยก volume ได้

## 11. Performance Budget

เป้าหมายหลักคือ 60 FPS บนเครื่องระดับกลางในฉากทั่วไป และ 30 FPS ขั้นต่ำชั่วคราวในฉากหนัก เฟรม time ต้องวัดแยก Game Thread, Render Thread, GPU, loading hitch และ memory ไม่ใช้ FPS เฉลี่ยเพียงค่าเดียวเป็นเกณฑ์

| รายการ | งบเริ่มต้นสำหรับการตรวจสอบ |
|---|---:|
| Game Thread | ไม่เกิน 6.0 ms |
| Render Thread | ไม่เกิน 3.5 ms |
| GPU | ไม่เกิน 12.0 ms |
| Memory | เหลือ headroom อย่างน้อย 15% จากเพดาน target platform |
| Streaming | ไม่มี hitch รุนแรงระหว่างเส้นทางมาตรฐาน |
| Network | tick และ bandwidth คงที่เมื่อมี 4 คน |

ทีมต้องทำ capture ซ้ำบนเครื่องจริงด้วย Unreal Insights, Stat Unit, Stat GPU, MemReport, Memory Insights และ network profiling เมื่อ build ใหม่ทำให้ฉากมาตรฐานแย่ลงเกิน threshold ต้องเปิด regression issue ก่อน merge

## 12. QA, Accessibility และ Release Gate

การทดสอบครอบคลุม unit, functional, integration, performance, network, compatibility, accessibility และ playtest ผู้เล่นจริง กรณีทดสอบต้องรวมการปิดเกมระหว่างเซฟ หลุดขณะจับอีโค วางฐานขอบเซลล์ สร้างของพร้อมกัน และเปิดเมนูระหว่างถูกโจมตี

เกมต้องมี subtitle ปรับขนาด speaker label, colorblind-safe indicator, remap ปุ่มเต็มรูปแบบ, toggle/hold, aim assist, camera shake slider, motion blur toggle, flashing reduction และ high contrast mode การทดสอบต้องทำทั้งเมาส์ คีย์บอร์ด และคอนโทรลเลอร์

| Gate | สิ่งที่ต้องพิสูจน์ |
|---|---|
| Prototype | movement, camera, combat, capture และ feedback สนุกพอ |
| Vertical Slice | core loop จบได้ใน 45–90 นาที มีฐานและ save/load |
| Co-op | 4 คนเล่นร่วมกันได้ ไม่มี dupes/desync สำคัญ |
| Content Alpha | ระบบหลักครบและเติมคอนเทนต์ผ่าน data ได้ |
| Beta | bug สำคัญต่ำ performance/accessibility/localization ผ่าน |
| Release Candidate | ไม่มี blocker, crash และ save migration ที่ทำลายข้อมูล |

## 13. Roadmap การผลิต

แผนเต็มควรทำเป็น Pre-production 4–8 สัปดาห์, Prototype 8–12 สัปดาห์, Vertical Slice 4–6 เดือน, Co-op Foundation 2–4 เดือน, Content Alpha 6–10 เดือน และ Beta/Polish 4–8 เดือน โดยเวลาจริงขึ้นกับทีมและ asset pipeline แนวทางที่ปลอดภัยที่สุดคือไม่เพิ่มจำนวนเขตหรืออีโคจนกว่า Vertical Slice จะพิสูจน์ว่าเกมสนุกและลื่น

ทีมขั้นต่ำสำหรับ Vertical Slice ควรมีผู้ดูแลวิสัยทัศน์/โปรดิวเซอร์, lead programmer, gameplay programmer, technical/network programmer, environment artist, creature artist, animator/VFX/audio, designer และ QA/playtest โดยบางบทบาทรวมกันได้ แต่ทุกระบบต้องมีเจ้าของและผู้ตรวจรับ

| ลำดับ | งาน Vertical Slice | ผลตรวจรับ |
|---:|---|---|
| 1 | Project setup, source control และ build | ทุกคนเปิดและสร้าง build ได้ |
| 2 | Movement, camera และ input | เดิน วิ่ง กระโดด หลบ และปรับค่าได้ |
| 3 | Interaction และ collection | เก็บของและ feedback ครบ |
| 4 | Echo prototype 3 ชนิด | ต่างกันด้าน behavior, ability และ utility |
| 5 | Combat/status | มี telegraph, hit reaction และจุดอ่อน |
| 6 | Capture/relationship | จับได้และเซฟข้อมูลถูกต้อง |
| 7 | Craft/base | สร้างจุดพักและผลิตของได้ |
| 8 | Quest/tutorial | ผู้เล่นใหม่ทำ core loop จบได้ |
| 9 | Save/load/migration | ปิดเปิดใหม่แล้วข้อมูลถูกต้อง |
| 10 | World/streaming/perf | เดินในเขตโดยไม่มี hitch สำคัญ |
| 11 | Co-op spike | ตรวจ ownership และ authority |
| 12 | Playtest/polish | ข้อมูลทดสอบนำไปปรับ build ถัดไป |

## 14. สิ่งที่ต้องทำต่อทันที

ขั้นต่อไปไม่ใช่การสร้างโลกห้าทวีป แต่คือการสร้าง Vertical Slice ใน Unreal Engine ให้เปิดเล่นได้จริง เริ่มจาก Third Person C++ project สำหรับ PC ตั้ง source control และโครงสร้างโมดูล สร้าง map ทดสอบเล็ก แล้วทำวงจรเก็บทรัพยากร → คราฟต์ → สร้างจุดพัก → ออกสำรวจ → จับอีโค → กลับฐาน

ควรสร้างอีโคต้นแบบสามตัวจาก Data Asset เดียวกันแต่มี behavior, ability และ utility ต่างกัน เพิ่ม save/load และ performance capture ก่อนทำ asset ความละเอียดสูง จากนั้นทดสอบกับผู้เล่นกลุ่มเล็ก ตัดสิ่งที่ไม่สนุก และค่อยทำ Co-op spike หากยังไม่มีโฟลเดอร์โครงการที่ผูกกับพื้นที่ทำงานจริง ผู้ใช้ควรเลือกหรือผูกโฟลเดอร์ก่อนเริ่มใส่ไฟล์ Unreal จำนวนมาก เพื่อป้องกันไฟล์กระจายหรือสูญหาย

เอกสารชุดนี้เป็น **pre-production package** ยังไม่ใช่เกม Unreal ที่คอมไพล์พร้อมเล่น เพราะการสร้างและทดสอบ C++ module, Blueprint, animation, asset และ Editor ต้องทำในเครื่องที่ติดตั้ง Unreal Engine การพัฒนาขั้นต่อไปควรเกิดในโฟลเดอร์โครงการจริงที่ทีมเข้าถึงได้

## 15. Definition of Success

ASTRAWILD รุ่นต้นแบบถือว่าประสบความสำเร็จเมื่อผู้เล่นใหม่เข้าใจและเล่น core loop ได้โดยไม่ต้องมีคนอธิบาย รู้สึกอยากลองอีโคตัวอื่น เห็นประโยชน์ของการกลับฐาน และพบว่าการเดินทางมีความหมาย เกมต้องควบคุมได้ดีบน target hardware มี save/load ที่เชื่อถือได้ และไม่พึ่ง Multiplayer เพื่อกลบปัญหาของแกนเกม

รุ่นเปิดตัวถือว่าประสบความสำเร็จเมื่อโลกมีเอกลักษณ์ อีโคมีบทบาทจริง ฐานช่วยการสำรวจ Co-op ไม่ทำลายข้อมูล ทีมเพิ่มคอนเทนต์ผ่าน data-driven pipeline ได้ และทุกการเพิ่มกราฟิกมี performance budget รองรับ
