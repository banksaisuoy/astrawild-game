# ASTRAWILD — Game Design Specification: Core Gameplay

## 1. หลักการออกแบบ

ระบบเกมของ ASTRAWILD ต้องทำให้ผู้เล่นรู้สึกว่า “ทุกการเดินทางมีการเตรียมตัว ทุกการพบอีโคมีวิธีรับมือมากกว่าหนึ่งแบบ และทุกทรัพยากรช่วยเปิดทางเลือกใหม่” เกมจะหลีกเลี่ยงการบังคับให้ผู้เล่นทำกิจกรรมเดิมซ้ำโดยไม่มีผลลัพธ์ที่มองเห็นได้ ความก้าวหน้าจะเกิดทั้งจากค่าตัวเลข ความรู้ของผู้เล่น และการเปลี่ยนแปลงของฐานหรือพื้นที่

เพื่อรักษาความสนุก ระบบทุกระบบต้องผ่านหลัก **อ่านง่าย ตอบสนองดี มีเหตุผล และเชื่อมต่อกัน** เช่น อาหารไม่ใช่เพียงตัวเลขลดความหิว แต่ต้องมีผลต่อการออกเดินทางและความสามารถของอีโค วัสดุไม่ใช่เพียงของขาย แต่ต้องนำไปสร้างเส้นทาง อุปกรณ์ หรือสิ่งอำนวยความสะดวกที่ทำให้ผู้เล่นสำรวจได้ไกลขึ้น

## 2. ผู้เล่นและการควบคุม

ผู้เล่นใช้มุมมองบุคคลที่สามแบบไหลลื่น กล้องมีระยะปรับได้และมีโหมดเล็งที่ทำให้การต่อสู้ระยะไกลแม่นยำขึ้น การเคลื่อนที่จะรองรับเดิน วิ่ง กระโดด ปีนขอบ ว่ายน้ำ ลื่นไถล และหลบหลีก แต่ความสามารถทั้งหมดจะถูกปลดล็อกหรือปรับปรุงจากอุปกรณ์และอีโคเพื่อให้การสำรวจมีความก้าวหน้า

| หมวด | ฟังก์ชันหลัก | ข้อกำหนดคุณภาพ |
|---|---|---|
| การเคลื่อนที่ | เดิน วิ่ง กระโดด หลบ ว่าย ปีน และใช้อุปกรณ์ช่วย | อินพุตตอบสนองเร็ว กล้องไม่ชนฉาก และมีระบบกันติด |
| การโต้ตอบ | เก็บของ ใช้เครื่องมือ เปิดประตู อ่านร่องรอย และคุยกับ NPC | มีไฮไลต์วัตถุที่อ่านง่ายและไม่ต้องกดพิกเซลเล็ก ๆ |
| การต่อสู้ | โจมตีเบา โจมตีหนัก อาวุธระยะไกล สกิล และหลบ | มี telegraph ชัดเจน hit reaction และ feedback ทางเสียง/ภาพ |
| การจัดการ | อินเวนทอรี แผนที่ ทีมอีโค เควสต์ และฐาน | เปิดใช้งานเร็ว แบ่งหมวด ค้นหาได้ และรองรับคอนโทรลเลอร์ |
| การสื่อสาร | Ping, คำสั่งทีม, emote และข้อความสั้น | ใช้ได้โดยไม่ต้องพิมพ์ และไม่บังคับใช้ voice chat |

ระบบควบคุมต้องมีการปรับแต่งปุ่ม ความไวกล้อง กลับแกน การสั่นของจอย ขนาดข้อความ สีของ UI และโหมดช่วยเล็ง ผู้เล่นควรเลือกเปิดการเก็บของอัตโนมัติหรือกดเก็บเองได้ รวมถึงเลือกให้เกมหยุดเมื่อเปิดเมนูใน Single-player

## 3. สถานะการเอาชีวิตรอด

เกมจะใช้สถานะจำนวนน้อยแต่มีความหมาย ไม่ใช้แถบความต้องการจำนวนมากจนทำให้เกมกลายเป็นการบริหารตัวเลขตลอดเวลา ค่าพลังชีวิตและความอึดเป็นค่าหลัก ส่วนความหิว ความกระหาย อุณหภูมิ และพิษเป็นสถานะที่เกิดจากพื้นที่หรือกิจกรรม ไม่ควรลดเร็วในพื้นที่ปลอดภัย

| สถานะ | ผลต่อผู้เล่น | วิธีจัดการ | แนวทางไม่ให้สร้างภาระ |
|---|---|---|---|
| พลังชีวิต | หมดแล้วล้มและเสียทรัพยากรบางส่วนตามโหมด | อาหาร ยา พัก และการช่วยเหลือ | ไม่ลดเองโดยไม่มีเหตุผล |
| ความอึด | จำกัดการวิ่ง หลบ ปีน และโจมตีหนัก | พัก อาหาร และอุปกรณ์ | ฟื้นเร็วเมื่อไม่ถูกโจมตี |
| ความหิว | ลดประสิทธิภาพเล็กน้อยและกระทบความสัมพันธ์กับอีโค | อาหารปรุง | ใช้ช่วงเวลาหลายสิบนาที ไม่ใช่ทุกนาที |
| ความกระหาย | ลดความอึดและทำให้เดินทางไกลยาก | น้ำสะอาดและเครื่องกรอง | แหล่งน้ำแสดงบนแผนที่หลังค้นพบ |
| อุณหภูมิ | ทำให้เกิดสถานะหนาวหรือร้อนในเขตพิเศษ | เสื้อผ้า อาหาร และที่พัก | ใช้เฉพาะพื้นที่ที่ควรมีความท้าทาย |
| สารพิษ | ลดพลังชีวิตหรือขัดจังหวะการควบคุม | ยา หน้ากาก และอีโคต้านพิษ | ให้ผู้เล่นมีสัญญาณเตือนก่อนเสมอ |

## 4. ระบบการต่อสู้

การต่อสู้เน้นการอ่านพฤติกรรมและการจัดทีม ไม่ใช่การกดโจมตีรัว ๆ ผู้เล่นถืออาวุธได้หนึ่งชุดและมีอีโคภาคสนามสูงสุดสามตัว ระบบจะมีสลับอีโคแบบรวดเร็ว คำสั่งพื้นฐาน เช่น โฟกัสเป้าหมาย ป้องกันพื้นที่ ถอยกลับ และใช้ความสามารถเฉพาะ การโจมตีของอีโคต้องมีกรอบเวลาและระยะที่อ่านได้เพื่อให้ผู้เล่นรู้สึกว่าชนะจากการตัดสินใจ

ศัตรูและอีโคจะมี “พฤติกรรมตอบสนอง” เช่น ตกใจเมื่อเพื่อนร่วมฝูงล้ม หนีเมื่อพลังชีวิตต่ำ เรียกฝูงเมื่อถูกรบกวน หรือเปลี่ยนรูปแบบการโจมตีเมื่ออากาศเปลี่ยน บอสจะใช้ช่วงเฟสที่แตกต่างกัน แต่ไม่ควรเพิ่มเลือดอย่างเดียว ความยากควรมาจากการเปลี่ยนกติกาของสนามและการบังคับให้ผู้เล่นใช้ความสามารถหลายแบบ

| ส่วนต่อสู้ | รุ่นเริ่มต้น | รุ่นขยาย |
|---|---|---|
| อาวุธผู้เล่น | ธนูพลังงาน หอกสั้น เครื่องมืออเนกประสงค์ | อาวุธระยะไกลหลายประเภท อาวุธประชิด และเครื่องมือควบคุมพื้นที่ |
| สกิล | สกิลติดตัว 2 ช่อง สกิลใช้งาน 2 ช่อง | Loadout ตามบทบาท และสกิลผสมธาตุ |
| ธาตุ | แสง เถ้า พฤกษา น้ำแข็ง และคลื่น | ปฏิกิริยาระหว่างธาตุและภูมิอากาศ |
| การป้องกัน | หลบ ปัดป้อง หรือใช้โล่ชั่วคราว | อุปกรณ์สร้างกำแพงและการประสานทีม |
| สถานะศัตรู | เผา แช่แข็ง ช็อก ช้าลง และแตกเกราะ | สถานะเฉพาะบอสและจุดอ่อนตามสภาพแวดล้อม |
| ผลแพ้ชนะ | ล้มและตื่นที่จุดพัก เสียของบางส่วนตามระดับความยาก | โหมดท้าทายที่ปรับความเสี่ยงได้โดยสมัครใจ |

## 5. ระบบค้นพบและจับอีโค

ผู้เล่นมี “สมุดภาคสนาม” ที่ไม่ได้ปลดล็อกข้อมูลทั้งหมดเมื่อเห็นอีโคครั้งแรก แต่จะค่อย ๆ เติมจากการสังเกต ติดตาม ให้อาหาร ต่อสู้ ช่วยเหลือ และพบในสภาพอากาศที่ต่างกัน สมุดนี้จะบอกข้อมูลที่เป็นประโยชน์ต่อการเล่น เช่น อาหารที่ชอบ ช่วงเวลาที่ออกหาอาหาร จุดอ่อน และความสามารถที่อาจฝึกได้

การจับประกอบด้วยสามเส้นทาง ได้แก่ การควบคุมสถานการณ์ด้วยอุปกรณ์ การสร้างความไว้ใจด้วยอาหารหรือภารกิจ และการช่วยอีโคออกจากอันตราย วิธีเหล่านี้อาจนำไปสู่ผลลัพธ์ที่แตกต่างกัน เช่น ค่าความไว้ใจเริ่มต้นสูงขึ้น ความสามารถเฉพาะติดตัวต่างกัน หรือเกิดเควสต์ต่อเนื่องกับฝูงของมัน

อีโคหนึ่งตัวไม่ได้มีค่าเพียงระดับหรือความหายาก แต่มี “รูปแบบชีวิต” ที่กำหนดว่าเหมาะกับทีมประเภทใด อีโคที่มีสถิติไม่โดดเด่นอาจมีบุคลิกที่ทำงานฐานดี หรือมีความสามารถภาคสนามที่ช่วยให้เข้าถึงพื้นที่ลับได้ จึงไม่ควรออกแบบให้ตัวหายากชนะทุกตัวแบบเด็ดขาด

## 6. ความสัมพันธ์และการพัฒนาอีโค

ความสัมพันธ์วัดจากการดูแล การพาไปทำกิจกรรมที่เหมาะกับบุคลิก การรักษาเมื่อล้ม และการใช้ความสามารถอย่างมีขอบเขต หากผู้เล่นใช้ตัวเดิมต่อเนื่อง อีโคจะเรียนรู้ท่าทางหรือพฤติกรรมบางอย่าง แต่จะเกิดความเหนื่อยล้าหากถูกใช้งานโดยไม่พัก ทำให้ผู้เล่นมีเหตุผลที่จะหมุนเวียนทีม

| ระดับ | สิ่งที่เพิ่มขึ้น | ผลต่อเกม |
|---|---|---|
| รู้จัก | ข้อมูลพื้นฐานและความชอบ | เปิดสูตรอาหารหรืออุปกรณ์ที่เหมาะ |
| คุ้นเคย | คำสั่งตอบสนองเร็วขึ้น | ใช้คำสั่งภาคสนามได้แม่นขึ้น |
| ไว้ใจ | ความสามารถร่วมทีม | ปลดล็อกคอมโบหรือช่วยเหลือฉุกเฉิน |
| ผูกพัน | เหตุการณ์เฉพาะตัว | เปิดเส้นทางเรื่องราวและสายพัฒนาพิเศษ |
| คู่หู | ความสามารถเอกลักษณ์ | เปลี่ยนวิธีที่ผู้เล่นสำรวจหรือสู้ |

## 7. ฐานและการสร้าง

ฐานเป็นพื้นที่ที่ผู้เล่นวางแผนและทำให้รู้สึกว่าโลกเป็นของตนเอง แต่ระบบจะไม่บังคับให้สร้างผนังทุกชิ้นแบบละเอียดตั้งแต่ต้น เกมจะมีชิ้นส่วนแบบ snap ที่วางง่าย มีระบบตรวจสอบพื้นและการชนที่เข้าใจได้ และมีโหมดแก้ไขที่ย้ายหรือรื้อสิ่งปลูกสร้างได้โดยสูญเสียวัสดุน้อยในช่วงต้น

ฐานแบ่งเป็นโซนใช้งาน ได้แก่ ที่พัก การผลิต ฟาร์ม การวิจัย การฝึกอีโค การป้องกัน และคลังสินค้า ผู้เล่นกำหนดงานให้อีโคผ่านลำดับความสำคัญและเงื่อนไขง่าย ๆ ไม่ต้องควบคุมทุกขั้นตอน เมื่อฐานเติบโตจะมีปัญหาพลังงาน การขนส่ง และความปลอดภัยเพิ่มขึ้น เพื่อให้การสร้างใหญ่ขึ้นมาพร้อมกับการตัดสินใจ ไม่ใช่เพียงการวางของเพิ่ม

| ระบบฐาน | ตัวอย่าง | ความสนุกที่ต้องสร้าง |
|---|---|---|
| การผลิต | เตาหลอม เครื่องปรุง โต๊ะประดิษฐ์ | เปลี่ยนของธรรมดาเป็นอุปกรณ์สำหรับพื้นที่ใหม่ |
| ฟาร์ม | พืชอาหาร พืชยา และพืชพลังงาน | วางแผนตามฤดูกาลและความต้องการของทีม |
| อีโคทำงาน | ตัดไม้ ขุดแร่ ดูแลพืช วิจัย และเฝ้ายาม | จัดคนให้เหมาะกับงานและแก้ปัญหาเมื่อมีเหตุการณ์ |
| พลังงาน | แผงแสง แกนพลังงาน และแบตเตอรี่ | เลือกว่าจะจ่ายไฟให้ระบบใดก่อน |
| การป้องกัน | ประตู ป้อม สัญญาณเตือน และเขตกั้น | รับมือการบุกโดยไม่เปลี่ยนเกมเป็น tower defense เต็มรูปแบบ |
| ความสวยงาม | ไฟ ป้าย เฟอร์นิเจอร์ และสีวัสดุ | ทำให้ฐานเป็นพื้นที่ที่ผู้เล่นอยากกลับมา |

## 8. คราฟต์และเศรษฐกิจ

ทรัพยากรแบ่งเป็นทรัพยากรธรรมชาติ วัตถุดิบแปรรูป ชิ้นส่วนเทคโนโลยี และของหายากจากเหตุการณ์ ไม่ควรมีทรัพยากรที่แตกต่างกันเพียงชื่อแต่ใช้งานเหมือนกันทั้งหมด วัตถุดิบแต่ละชนิดต้องมีเหตุผลในการเก็บ เช่น ทำอุปกรณ์กันหนาว ใช้ขยายคลัง หรือเป็นอาหารโปรดของอีโค

เศรษฐกิจภายในเกมใช้การแลกเปลี่ยนกับชุมชนมากกว่าตลาดที่มีตัวเลขซับซ้อน ผู้เล่นเลือกช่วยชุมชนใด จะส่งผลต่อสินค้าที่หาได้ เส้นทางการค้า และเควสต์บางประเภท เงินหรือเครดิตมีไว้ลดการฟาร์มซ้ำ ไม่ใช้เป็นทางลัดที่ทำให้ระบบคราฟต์ไร้ความหมาย

## 9. เควสต์และเรื่องราว

เควสต์หลักจะพาผู้เล่นไปหาแกนเรื่องของหอดูดาวและความจริงเกี่ยวกับรุ่งอรุณแตกสลาย ส่วนเควสต์รองจะใช้ระบบโลกเป็นตัวสร้างเรื่อง เช่น ฝูงอีโคหายไปจากพื้นที่ ชุมชนขาดน้ำ เครื่องจักรเก่าทำงานผิดปกติ หรืออีโคที่เคยช่วยไว้นำทางกลับมาหาผู้เล่น

เควสต์ไม่ควรเป็นเพียงการเดินไปฆ่าศัตรูตามจำนวน แต่ต้องมีตัวเลือก เช่น ช่วย เจรจา สืบสวน ทดลอง หรือแลกเปลี่ยน การตัดสินใจจะส่งผลในระดับที่ทีมสร้างดูแลได้ เช่น เปลี่ยน NPC หนึ่งกลุ่ม เปิดร้านใหม่ ย้ายจุดทรัพยากร หรือเพิ่มเหตุการณ์ในเขตหนึ่ง ไม่จำเป็นต้องทำ branching story ขนาดมหาศาลตั้งแต่ต้น

## 10. โหมดเล่นร่วมกัน

Co-op ออกแบบให้ทุกคนมีส่วนร่วมโดยไม่ล็อกบทบาทถาวร ผู้เล่นหนึ่งอาจสร้างฐาน อีกคนสำรวจ อีกคนดูแลอีโค หรือทุกคนรวมทีมต่อสู้ก็ได้ ความคืบหน้าของโลกและของผู้เล่นต้องแยกกันอย่างชัดเจน โดยเจ้าของโลกเป็นผู้กำหนดการเปลี่ยนแปลงแผนที่ ส่วนผู้มาเยือนยังเก็บอุปกรณ์ ความรู้ และความสัมพันธ์ของตนเองได้

ในช่วงต้นใช้ Host/Listen Server เพื่อทดสอบระบบและลดต้นทุน แต่โค้ดการเล่นต้องใช้ server authority: การสร้างไอเทม การจับอีโค การทำดาเมจ และการเปลี่ยนสถานะฐานต้องตรวจสอบจากเซิร์ฟเวอร์เสมอ การใช้ Iris ควรประเมินหลังระบบพื้นฐานเสถียร เพราะเอกสารทางการระบุว่า Iris เป็นระบบ opt-in และยังมีสถานะ Experimental ในเอกสารรุ่นปัจจุบัน [1]

| สถานะ | เจ้าของหลัก | ตัวอย่าง |
|---|---|---|
| ผู้เล่น | ผู้เล่นคนนั้น | อุปกรณ์ สกิล สมุดภาคสนาม และอีโคส่วนตัว |
| ปาร์ตี้ | ทีม | เป้าหมายภารกิจ เงินรางวัล และการเชิญร่วม |
| โลก | เจ้าของเซสชัน | การปลดล็อกพื้นที่ หอดูดาว และการเปลี่ยนแปลงชุมชน |
| ฐาน | เจ้าของโลกหรือสิทธิ์ที่กำหนด | สิ่งปลูกสร้าง งานผลิต และคลังทีม |
| เหตุการณ์ชั่วคราว | เซิร์ฟเวอร์ | พายุ ฝูงอีโค และการบุกฐาน |

## 11. การบันทึกและการกู้คืน

ระบบเซฟต้องรองรับ Manual Save, Auto Save, Quick Resume และ Backup Save อย่างน้อยสามช่อง การบันทึกไม่ควรเกิดกลางแอนิเมชันสำคัญหรือระหว่างการวางสิ่งปลูกสร้างโดยไม่สมบูรณ์ ข้อมูลต้องแยกเป็น Player Save, World Save และ Settings เพื่อให้ย้ายตัวละครไปเล่นกับโลกใหม่ได้ในอนาคตหากต้องการ

ทุกการบันทึกต้องมี version number และ migration function เพื่อรองรับการอัปเดตเกม หากข้อมูลเสียหาย เกมควรตรวจสอบ checksum และถอยกลับไปใช้ backup ล่าสุด โดยแจ้งผู้เล่นอย่างชัดเจนแทนที่จะลบไฟล์เงียบ ๆ

## 12. Definition of Fun สำหรับ Vertical Slice

Vertical Slice จะถือว่าผ่านเมื่อผู้เล่นใหม่สามารถเริ่มเกม เรียนรู้การเคลื่อนที่ จับอีโคตัวแรก สร้างจุดพัก ต่อสู้กับศัตรูระดับกลาง และกลับไปปรับปรุงอุปกรณ์ได้ภายใน 45–90 นาทีโดยไม่ต้องอ่านคู่มือยาว ผู้เล่นเดิมควรมีทางเลือกในการทดลองวิธีจับอีโคและจัดทีมต่างกันจนเกิดผลลัพธ์ที่แตกต่าง

การทดสอบต้องวัดทั้งความรู้สึกและข้อมูล เช่น ผู้เล่นรู้ว่าต้องทำอะไรต่อหรือไม่ กดผิดบ่อยตรงไหน เดินหลงเพราะแผนที่ไม่ชัดหรือไม่ อีโคมีประโยชน์จริงหรือผู้เล่นใช้เพียงตัวที่เก่งที่สุด และเฟรมเรตตกในช่วงใด ข้อมูลเหล่านี้จะเป็นเกณฑ์ก่อนขยายเขต แทนการตัดสินจากจำนวนระบบที่สร้างเสร็จ
