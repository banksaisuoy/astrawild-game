# ASTRAWILD — Art, World, Audio & Content Bible

## 1. ทิศทางศิลป์โดยรวม

ASTRAWILD ใช้สไตล์ **stylized naturalism** คือโลกมีสัดส่วนและแสงที่น่าเชื่อ แต่รูปร่าง สี และ silhouette ของอีโคมีความชัดเจนแบบงานแฟนตาซีร่วมสมัย เป้าหมายคือให้ผู้เล่นจำอีโคได้จากเงาร่างและสีหลักเมื่อเห็นจากระยะไกล ไม่พึ่งรายละเอียดจิ๋วหรือ texture ที่ต้องใช้ความละเอียดสูงตลอดเวลา

ภาพรวมควรสื่อความรู้สึกว่าโลกกำลังฟื้นตัวหลังอารยธรรมล่มสลาย ธรรมชาติไม่ได้เป็นเพียงฉากสีเขียว แต่มีร่องรอยพลังงานที่ค่อย ๆ แทรกอยู่ในรากไม้ หิน น้ำ และซากเครื่องจักร สีธรรมชาติใช้เป็นพื้นฐาน ส่วนสีเรืองแสงใช้เฉพาะจุดสำคัญ เพื่อรักษาลำดับความสนใจและไม่ทำให้ทุกอย่างเด่นเท่ากัน

| หมวด | แนวทาง |
|---|---|
| รูปทรง | ธรรมชาติที่มีโครงสร้างชัด ผสมชิ้นส่วนอารยธรรมที่เป็นเหลี่ยมและเส้นเรขาคณิต |
| สี | เขียวหม่น น้ำตาลดิน ฟ้าคราม และส้มอุ่นเป็นสีฐาน พลังงานใช้ฟ้าเรืองหรือม่วงเฉพาะจุด |
| วัสดุ | ไม้ หิน ผ้า โลหะเก่า และผลึกพลังงาน มีความแตกต่างทางผิวสัมผัสชัด |
| แสง | แสงธรรมชาติแบบอ่านง่าย ใช้ rim light และสีจากสภาพแวดล้อมช่วยแยกตัวละคร |
| เอฟเฟกต์ | มีน้ำหนักและทิศทาง ไม่ใช้ particle จำนวนมากเพื่อกลบการอ่าน gameplay |
| UI | เรียบ สะอาด ใช้สัญลักษณ์ที่จำได้เร็ว และรองรับผู้เล่นที่มีปัญหาการแยกสี |

## 2. การออกแบบอีโค

อีโคแต่ละชนิดต้องมี design pillar ของตัวเอง ได้แก่ habitat, silhouette, behavior, utility และ emotional hook ก่อนเริ่มปั้นโมเดล ต้องทำ thumbnail อย่างน้อย 20 แบบแล้วคัดให้เหลือ 3 แบบเพื่อทดสอบในเกมจากระยะกล้องจริง การออกแบบที่สวยในภาพระยะใกล้แต่แยกไม่ออกระหว่างการเล่นถือว่ายังไม่ผ่าน

อีโคไม่ควรใช้สูตร “สัตว์จริงบวกเขาหรือปีก” ทุกตัว แต่ควรเริ่มจากพฤติกรรมหรือระบบนิเวศ เช่น อีโคที่เก็บเสียงไว้ในเกราะ อีโคที่เปลี่ยนสีตามความชื้น หรืออีโคที่สร้างรังจากเศษโลหะ การออกแบบความสามารถต้องสะท้อนรูปลักษณ์และที่อยู่ ไม่ใช่ใส่ธาตุให้ครบตามตาราง

| ขั้นตอนผลิตอีโค | ผลลัพธ์ที่ต้องส่งมอบ |
|---|---|
| Research & silhouette | moodboard, keyword, silhouette sheet และ color key |
| Concept | turnaround, expression, scale comparison และ gameplay pose |
| Modeling | high/low mesh, UV, collision, material ID และ LOD/fallback policy |
| Rigging | skeleton, sockets, physical asset และ animation blueprint setup |
| Animation | locomotion, idle, threat, attack, damage, capture, work และ emotes |
| VFX & audio | trail, ability VFX, hit reaction, vocal set และ ambient behavior |
| Integration | data asset, AI state, ability set, spawn rule และ capture profile |
| QA | visual readability, collision, performance, save/load และ multiplayer |

## 3. สัดส่วนและความอ่านง่าย

ผู้เล่นต้องมองออกจากระยะไกลว่าอะไรคือเพื่อน ศัตรู ของเก็บได้ จุดโต้ตอบ และพื้นที่อันตราย การใช้สีแดงกับศัตรูทุกประเภทไม่เพียงพอ จึงควรใช้ shape language, movement language และ icon language ร่วมกัน อีโคที่เป็นมิตรเคลื่อนไหวเป็นจังหวะและมีเสียงตอบรับต่างจากศัตรูที่คอยล็อกเป้า

ทุกอีโคต้องมีอย่างน้อยสามระดับของ silhouette ได้แก่ ระยะใกล้สำหรับอารมณ์และรายละเอียด ระยะกลางสำหรับการต่อสู้และการเลือกเป้าหมาย และระยะไกลสำหรับการสังเกตในโลก หากอีโคมีพาหนะหรืออุปกรณ์สวมใส่ ส่วนประกอบต้องไม่บดบังจุดอ่านหลักของร่างกาย

## 4. โลกและการวางแผนแผนที่

การออกแบบแผนที่ใช้หลัก **landmark, loop และ reveal** ทุกพื้นที่ต้องมี landmark ที่ช่วยบอกตำแหน่ง มีเส้นทางหลักที่ปลอดภัย และเส้นทางรองที่เสี่ยงแต่ให้รางวัลสูง ผู้เล่นควรเห็นพื้นที่หรือสิ่งที่อยากไปก่อน แล้วค่อยค้นพบวิธีเข้าถึง แผนที่ไม่ควรเป็นพื้นราบใหญ่ที่ไม่มีจุดอ้างอิง

เขตหนึ่งควรมี hub, wilderness, challenge space, resource route และ story space ครบในสัดส่วนที่ต่างกัน เส้นทางกลับฐานต้องสั้นลงเมื่อผู้เล่นปลดล็อกสะพาน จุดพัก หรือความสามารถของอีโค เพื่อให้ความก้าวหน้าลดเวลาวิ่งย้อนกลับแทนที่จะเพิ่มระยะทางเรื่อย ๆ

| ชั้นของแผนที่ | ตัวอย่าง | วิธีสร้างความน่าสนใจ |
|---|---|---|
| อ่านจากไกล | ภูเขาหัก หอคอยเก่า ต้นไม้เรืองแสง | ใช้เป็นเข็มทิศธรรมชาติและเป้าหมายการเดินทาง |
| ระดับเดินทาง | ป่า แม่น้ำ ช่องเขา ซากสถานี | ทำให้ผู้เล่นเลือกเส้นทางและจัดการทรัพยากร |
| ระดับโต้ตอบ | ถ้ำ รัง ฝาย ประตูพลังงาน | ให้ใช้เครื่องมือหรืออีโคเฉพาะ |
| ระดับเรื่องราว | หอดูดาว ชุมชน โรงงานเก่า | ให้การตัดสินใจและเหตุการณ์เปลี่ยนพื้นที่ |
| ระดับความลับ | ทางลอด จุดชมวิว และห้องซ่อน | ให้รางวัลกับการสังเกต ไม่ใช่การเปิดแผนที่ครบทุกจุด |

## 5. การจัดการระดับรายละเอียดและกราฟิก

ทุก asset ต้องมี target platform tier ตั้งแต่วันที่เริ่มทำ โดยแบ่งเป็น Low, Medium, High และ Ultra แต่ละ tier จะกำหนด texture resolution, material features, shadow mode, effect density, foliage density และ view distance การทำงานแบบนี้ช่วยให้ทีมรักษาคุณภาพภาพโดยไม่ต้องทำ asset ใหม่ทั้งหมดเมื่อเปลี่ยนแพลตฟอร์ม

Nanite เหมาะกับฉาก static ที่มีรายละเอียดมากและต้องการการสตรีม geometry แต่ทีมต้องวัดผลเรื่อง material complexity, instance count, memory และ output resolution เพราะเอกสารทางการระบุว่ายังมีข้อจำกัดเชิงปฏิบัติแม้ระบบจะลดภาระเรื่อง polycount และ LOD ของ mesh ได้มาก [1] ตัวละครหลักและอีโคต้องมี animation budget และ fallback ที่รองรับเครื่องระดับกลาง

Lumen ใช้เป็นตัวเลือกคุณภาพสูงสำหรับแสงไดนามิกและการสะท้อน ส่วนฉากและวัสดุต้องยังอ่านได้เมื่อคุณภาพแสงลดลง เนื่องจาก Lumen มีต้นทุนเพิ่มตามระยะมองเห็น คุณภาพ final gather และคุณภาพ reflection [2]

| ระดับ | เป้าหมายประสบการณ์ | แนวทางภาพ |
|---|---|---|
| Low | เครื่องระดับเริ่มต้น | แสงราคาถูก เงาระยะสั้น พืชลดจำนวน วัสดุเรียบ |
| Medium | เครื่องเป้าหมายหลัก | เงาคุณภาพกลาง เอฟเฟกต์ครบ ลดระยะไกลบางส่วน |
| High | เครื่องเกมทั่วไป | Lumen คุณภาพกลาง/สูง Nanite เต็มในฉากที่เหมาะ |
| Ultra | เครื่องประสิทธิภาพสูง | ระยะวาดและ reflection สูงสุด ไม่ใช้เป็นเกณฑ์ออกแบบหลัก |

## 6. วัสดุและสีตามเขต

แต่ละเขตต้องมี material language ที่จำได้โดยไม่ต้องเห็นป้ายชื่อ ทุ่งอรุณใช้พื้นผิวอบอุ่นและเปิดโล่ง ป่าฝนเรืองแสงใช้ความชื้นและการสะท้อนแบบนุ่ม ที่ราบเกลือใช้พื้นผิวแตกและความพร่ามัวจากความร้อน แนวหิมะครามใช้ contrast สูงและขอบวัสดุที่สะท้อนแสง ส่วนซากมหานครใช้โลหะ oxidized แสงไฟฉุกเฉิน และพื้นผิวที่แสดงการแย่งพื้นที่ระหว่างธรรมชาติกับเครื่องจักร

Material master ต้องมี scalar/vector parameter ที่เหมือนกันใน asset family เพื่อให้เปลี่ยนฤดูกาล ความเปียก ฝุ่น หิมะ และพลังงานได้จากระบบเดียว แต่ไม่ควรสร้าง material permutation จำนวนมากโดยไม่ควบคุม การเปลี่ยนสภาพควรใช้ material parameter collection, decals ที่จำเป็น และระบบ foliage ที่ปรับตามระยะ

## 7. แอนิเมชันและความรู้สึกของการควบคุม

แอนิเมชันการเคลื่อนที่ต้องให้ความสำคัญกับ input latency และการเปลี่ยนทิศทางมากกว่าความสมจริงสูงสุด ใช้ motion matching หรือระบบ locomotion ที่เหมาะสมเมื่อทีมมีข้อมูลและงบเพียงพอ แต่ต้องมีระบบที่เสถียรและ debug ได้ก่อน อีโคแต่ละชนิดต้องมี idle ที่บอกบุคลิกอย่างน้อย 2–3 แบบ เพื่อไม่ให้โลกดูเหมือนมีหุ่นซ้ำกัน

การต่อสู้ต้องมี anticipation, active frame, recovery และ hit reaction ที่ชัด อาวุธและความสามารถจะใช้ animation montage ที่มี notify สำหรับ damage window, VFX, sound และ camera shake โดย notify เหล่านี้ต้องไม่เป็นแหล่งความจริงของกฎการโกงใน Multiplayer เพราะ server ต้องตรวจสอบการโจมตีแยกต่างหาก

## 8. VFX และการอ่านสถานะ

VFX แบ่งเป็น gameplay-critical และ atmosphere-only เอฟเฟกต์ gameplay-critical เช่น จุดอ่อน การจับสำเร็จ สถานะติดไฟ และพื้นที่อันตรายต้องมองเห็นได้ใน preset ต่ำและต้องมีเสียงหรือ UI สำรอง ส่วนหมอก เศษใบไม้ และประกายระยะไกลสามารถลดหรือปิดได้

สีของธาตุไม่ควรเป็นตัวบอกเพียงอย่างเดียว เนื่องจากผู้เล่นบางคนแยกสีได้ยาก ทุกสถานะจึงต้องมีรูปทรง pattern icon และเสียงประกอบร่วมด้วย พื้นที่ที่ทำดาเมจต้องบอกขอบเขตด้วย decal หรือการเปลี่ยนพื้นผิว ไม่พึ่ง particle ที่เคลื่อนที่เร็วเพียงอย่างเดียว

## 9. เสียงและดนตรี

เสียงแบ่งเป็น ambience, diegetic gameplay, character/echo vocal, UI และ music เสียงสิ่งแวดล้อมจะบอกความหนาแน่นของพื้นที่และภัยก่อนผู้เล่นมองเห็น ขณะที่เสียงฝีเท้าและการเคลื่อนที่ของอีโคต้องแตกต่างตามวัสดุและน้ำหนัก เพื่อช่วยการรับรู้โดยไม่ทำให้หน้าจอเต็มไปด้วยไอคอน

ดนตรีใช้ระบบ adaptive layers มีชั้นพื้นฐานสำหรับการสำรวจ ชั้นความตึงเครียดเมื่อเข้าสู่พื้นที่อันตราย และชั้นต่อสู้ที่เพิ่มตามจำนวนศัตรูหรือเฟสของบอส เพลงไม่ควรดังกลบเสียงสัญญาณ gameplay ผู้เล่นสามารถแยก volume ของ ambience, effects, dialogue, music และ accessibility cues ได้

## 10. เนื้อหาและจำนวนเป้าหมาย

เพื่อให้โปรเจกต์ใหญ่แต่ไม่หลุดการควบคุม คอนเทนต์ต้องสร้างจากชุดประกอบที่นำกลับมาใช้ได้ เช่น encounter archetype, quest objective, resource node, dungeon room, building kit และ animation set อีโคหนึ่งสายพันธุ์อาจมีหลาย habitat, behavior state และ visual variant ได้ แต่ variant ต้องมีความหมายด้านเกมหรือโลก ไม่ใช่เปลี่ยนสีเพื่อเพิ่มจำนวนบนหน้าร้าน

| คอนเทนต์ช่วง Launch | เป้าหมายที่แนะนำ |
|---|---:|
| เขตหลัก | 3–5 เขต |
| อีโคที่ออกแบบเต็มรูปแบบ | 35–50 ชนิด |
| อีโคสายพันธุ์พิเศษ/บอส | 5–8 ชนิด |
| อาวุธและเครื่องมือ | 12–18 ชิ้น |
| ชุดอาคาร | 6–8 วัสดุหลัก และ 60–100 ชิ้นส่วน |
| ดันเจียน/พื้นที่ท้าทาย | 8–12 แห่ง |
| เควสต์หลัก | 25–40 ตอน |
| เควสต์รองและเหตุการณ์ | 60–100 รายการแบบประกอบได้ |
| ชุดเสียงอีโค | อย่างน้อย 3 กลุ่มเสียงต่อชนิด |

ตัวเลขเหล่านี้เป็นเป้าหมายการวางแผน ไม่ใช่ข้อผูกมัดให้เพิ่มคอนเทนต์จนคุณภาพตก ทีมควรเปิดเกมด้วยจำนวนที่น้อยกว่าแต่มีความแตกต่างของการใช้งานจริง และวัด retention, bug rate, performance และเวลาผลิตก่อนขยายจำนวน

## 11. การผลิตคอนเทนต์และการตรวจรับ

แต่ละ asset ใช้สถานะ Concept, Blockout, In Production, Integrated, Playtest, Polish และ Approved เมื่อ asset ผ่านแต่ละสถานะต้องมีผู้รับผิดชอบและเกณฑ์ตรวจ เช่น naming, scale, collision, LOD, memory, material, animation, sound, localization และ save/load การตรวจรับไม่ควรดูเฉพาะภาพใน DCC หรือ Editor แต่ต้องทดสอบจากกล้องและระยะที่ผู้เล่นเห็นจริง

ทีมควรทำ content review รายสัปดาห์ที่เน้นคำถามสามข้อ คือผู้เล่นอ่านสิ่งนี้ออกหรือไม่ มีเหตุผลให้สนใจหรือไม่ และราคาประสิทธิภาพคุ้มค่าหรือไม่ หาก asset สวยแต่ทำให้ฉากตกเฟรมหรือทำให้ระบบอ่านยาก ต้องแก้ที่ต้นเหตุ ไม่ใช่เพิ่ม UI มาชดเชยทุกครั้ง

## 12. ภาษาและการเข้าถึง

ข้อความทุกส่วนต้องรองรับ localization ตั้งแต่ต้น ห้ามวางข้อความสำคัญเป็น texture ถาวร ควรกำหนดความยาวสูงสุดและตรวจการขยายของภาษาไทย อังกฤษ จีน ญี่ปุ่น และภาษาอื่นที่อาจเพิ่มภายหลัง ชื่ออีโคและคำศัพท์โลกควรมี glossary กลางเพื่อป้องกันการแปลไม่สม่ำเสมอ

ระบบเข้าถึงควรมี subtitle ปรับขนาด, speaker label, colorblind-safe indicators, hold/toggle options, aim assist, camera shake slider, motion blur toggle, flashing reduction, high contrast mode และการ remap ปุ่มเต็มรูปแบบ การรองรับเหล่านี้ต้องทดสอบร่วมกับ gameplay ไม่ใช่ใส่ในเมนูตอนท้ายโครงการ
